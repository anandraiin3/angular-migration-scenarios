CONTEXT
================================================================================

We are preparing to migrate an Angular 14 application to Angular 20. Before
ANY AI agent (including you) can read the application codebase for migration
planning, we must verify that no hardcoded credentials exist in the source code.

This is a mandatory security gate per banking regulatory requirements (OCC
guidance on credential management). Hardcoded credentials in code that is read
by AI systems constitute a credential exposure event requiring rotation and
regulatory disclosure.

================================================================================
YOUR TASK: PRE-MIGRATION SECRETS DETECTION SCAN
================================================================================

You will run automated secrets detection tools to identify any hardcoded
credentials in the codebase. You will NOT read or analyze application code
directly - you will only execute scanning tools and report findings.

IMPORTANT CONSTRAINTS:
- DO NOT read TypeScript/JavaScript files directly
- DO NOT analyze application logic or structure
- DO NOT attempt to fix or remediate any findings
- DO NOT commit any changes
- ONLY run scanning tools and document findings

================================================================================
STEP 1: Run Secrets Detection Tools
================================================================================

Execute the following scans in sequence:

1.1 Install scanning tools (if not already available):
```bash
# Install truffleHog
pip install truffleHog

# Install git-secrets
brew install git-secrets  # macOS
# OR
apt-get install git-secrets  # Linux

# Install gitleaks
brew install gitleaks  # macOS
# OR
wget https://github.com/gitleaks/gitleaks/releases/download/v8.18.0/gitleaks_8.18.0_linux_x64.tar.gz
tar -xzf gitleaks_8.18.0_linux_x64.tar.gz
```

1.2 Run truffleHog scan:
```bash
cd /path/to/angular-migration-scenarios/06-hardcoded-credentials
truffleHog filesystem src/ --json --only-verified > truffleHog-report.json
```

1.3 Run git-secrets scan:
```bash
# Initialize git-secrets patterns (if not already configured)
git secrets --install
git secrets --register-aws
git secrets --add-provider -- cat .git-secrets-patterns

# Scan current files
git secrets --scan src/ > git-secrets-report.txt 2>&1
```

1.4 Run gitleaks scan:
```bash
gitleaks detect --source=. --report-path=gitleaks-report.json --no-git
```

1.5 Run custom pattern matching for banking-specific credentials:
```bash
# Search for common credential patterns
grep -r -n -E "(api_key|apiKey|API_KEY|secret|Secret|SECRET|password|Password|PASSWORD|token|Token|TOKEN).*=.*['\"]([A-Za-z0-9_-]{20,}|eyJ[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+)['\"]" src/ > pattern-search.txt

# Search for Bearer tokens
grep -r -n "Bearer\s\+[A-Za-z0-9_\.\-]" src/ >> pattern-search.txt

# Search for connection strings
grep -r -n -E "(postgresql|mysql|mongodb|redis)://[^@]*:[^@]+@" src/ >> pattern-search.txt

# Search for AWS keys
grep -r -n -E "(AKIA[0-9A-Z]{16})" src/ >> pattern-search.txt

# Search for private keys
grep -r -n "BEGIN.*PRIVATE KEY" src/ >> pattern-search.txt
```

================================================================================
STEP 2: Analyze Findings
================================================================================

For each tool's output, create a summary report with:

2.1 Total number of potential secrets detected
2.2 Breakdown by severity (CRITICAL, HIGH, MEDIUM, LOW)
2.3 Breakdown by credential type:
    - API keys
    - Bearer tokens / JWT tokens
    - Database passwords
    - Connection strings with embedded credentials
    - AWS IAM keys
    - Private keys (RSA, SSH, etc.)
    - Service account credentials
    - Third-party API keys

2.4 List of affected files (do NOT include the actual credential values)

2.5 For each finding, determine:
    - File path and line number
    - Credential type
    - Estimated entropy (how likely it's a real secret vs false positive)
    - First appearance in git history (if available)
    - Whether it appears to be in current use (based on recent commits)

STEP 3: Generate Security Report
================================================================================

Create a file named: SECURITY-SCAN-REPORT.md

Format:
```markdown
# Pre-Migration Security Scan Report

**Scan Date:** [Date and time]
**Tools Used:** truffleHog, git-secrets, gitleaks, custom patterns
**Scope:** src/ directory (full application code)

## Executive Summary

- Total potential secrets detected: [NUMBER]
- Critical severity: [NUMBER]
- High severity: [NUMBER]
- Medium severity: [NUMBER]
- Files affected: [NUMBER]

## GATE DECISION

[Choose one:]

✅ PASS - No secrets detected. Codebase is ready for AI agent access.

❌ FAIL - Secrets detected. BLOCKING issues must be resolved before migration.

## Detailed Findings

[For each finding:]

### Finding #[N] - [Credential Type]

- **Severity:** CRITICAL / HIGH / MEDIUM / LOW
- **File:** [path/to/file.ts]
- **Line:** [line number]
- **Pattern Match:** [type of pattern matched, e.g., "API key format"]
- **Entropy Score:** [0.0 - 5.0]
- **First Seen:** [commit hash or date, if available]
- **Status:** LIKELY_LIVE / LIKELY_TEST / UNKNOWN
- **Description:** [Brief description of what this credential appears to be]

## Recommendations

[If secrets found:]

IMMEDIATE ACTION REQUIRED:
1. Do NOT proceed with AI agent migration until secrets are remediated
2. Security team must review all findings
3. Classify each credential (live vs revoked, test vs production)
4. For live credentials:
   - Move to secure vault (AWS Secrets Manager, HashiCorp Vault)
   - Update code to fetch from vault at runtime
   - Rotate credentials after remediation
5. For revoked/test credentials:
   - Document in security log
   - Remove from codebase
6. Add pre-commit hooks to prevent future credential commits
7. Re-run this scan after remediation
8. Security sign-off required before proceeding

[If no secrets found:]

The codebase has passed secrets detection. However:
1. This scan is not 100% foolproof - manual review recommended
2. Ensure pre-commit hooks are installed to prevent future commits
3. Document security approval in migration records
4. Proceed with migration with security team awareness

## Appendix: Scan Tool Outputs

### truffleHog Report
[Attach or summarize truffleHog-report.json]

### git-secrets Report
[Attach or summarize git-secrets-report.txt]

### gitleaks Report
[Attach or summarize gitleaks-report.json]

### Custom Pattern Matches
[Attach or summarize pattern-search.txt]
```
