DEVIN SESSION PROMPT - Sanitization Bypass Audit for Angular 20 Migration

==============================================================================
CONTEXT
==============================================================================

You are performing a pre-migration security audit for Bank of America's Consumer Banking Portal (59 million active customers). The application is currently on Angular 14.2.0 and is scheduled for migration to Angular 20.0.0 in 3 weeks.

Your task is to implement Playbook Rule 8.4: Sanitization Bypass Audit.

This rule exists because Angular 20 changed its security architecture to rely on Content Security Policy (CSP) for XSS prevention. In Angular 14, the framework's sanitizer provides fallback protection even when developers use bypassSecurity* methods. In Angular 20, bypassed content is NOT sanitized by Angular—it's subject only to the page's CSP policy. If CSP is misconfigured or absent, XSS payloads will execute.

**Regulatory Context:**
This is a federally regulated financial institution. XSS vulnerabilities that result in session theft or account takeover trigger mandatory incident reporting under GLBA (Gramm-Leach-Bliley Act) and OCC (Office of the Comptroller of the Currency) supervision. An exploited XSS vulnerability could result in:
- Federal regulatory incident disclosure
- OCC examination
- Civil penalties (up to $1M per violation)
- Customer notification requirements
- Reputation damage

Your audit is a BLOCKING GATE for the Angular 20 migration. The migration cannot proceed until all high-risk sanitization bypasses are remediated or properly protected with CSP.
