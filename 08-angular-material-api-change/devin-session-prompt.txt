TASK: Angular Material API Audit and Migration Plan

CONTEXT:
We need to upgrade from Angular Material 14.2.0 to Material 15.2.0 in our banking application. A previous migration attempt failed because breaking changes were discovered reactively during QA testing, leading to a rollback after 3 hours of wasted effort.

The application uses Angular Material extensively for forms, tables, and dialogs. We need a comprehensive audit of ALL Material API usage before attempting the upgrade again.

OBJECTIVE:
Perform a systematic audit of the entire codebase to identify every instance of deprecated or changed Material APIs. Create a detailed migration plan with file-level changes required.

SPECIFIC TASKS:

1. API USAGE AUDIT

Search the codebase for the following deprecated patterns and document EVERY occurrence:

a) MatFormField appearance="legacy"
   - Search pattern: appearance="legacy"
   - Expected locations: Form components, input fields
   - Required change: Replace with "fill", "outline", or remove for default

b) Direct MatTableDataSource array assignment
   - Search pattern: .dataSource = (without 'new MatTableDataSource')
   - Expected locations: Table components, list views
   - Required change: Wrap arrays with new MatTableDataSource(data)

c) MatDialog loose typing
   - Search pattern: dialog.open( (without generic type parameters)
   - Expected locations: Services, components with dialogs
   - Required change: Add proper generic types MatDialog.open<Component, Data, Result>

d) Other Material 15 breaking changes
   - Review Angular Material 15 changelog
   - Search for any additional deprecated APIs
   - Document findings

2. IMPACT ANALYSIS

For each pattern found, provide:
- File path and line number
- Current code snippet
- Recommended replacement code
- Risk level (High/Medium/Low)
- Affected functionality description

3. MIGRATION PLAN

Create a structured migration plan with:

Phase 1: Low-risk changes (components not customer-facing)
Phase 2: Medium-risk changes (internal tools, dashboards)
Phase 3: High-risk changes (customer-facing forms, transactions)

For each phase:
- List of files to modify
- Estimated time per file
- Testing requirements
- Rollback plan

4. TEST STRATEGY

Define test cases for:
- Visual regression tests (screenshot comparison)
- Functional tests (form submission, table filtering, dialog flows)
- Integration tests (complete user workflows)

5. DELIVERABLES

Provide these artifacts:
- migration-audit.csv: Complete list of affected files with details
- migration-plan.md: Step-by-step migration instructions
- test-checklist.md: Testing requirements before deployment
- rollback-procedure.md: Quick rollback steps if issues found

CONSTRAINTS:

- DO NOT make any code changes yet - this is audit-only
- DO NOT skip any files - we need 100% coverage
- DO NOT assume patterns - search exhaustively
- DO prioritize by customer impact

CRITICAL REQUIREMENTS:

1. Search the ENTIRE src/ directory recursively
2. Include component files (.ts), template files (.html), and style files (.scss)
3. Check for both explicit Material imports and template usage
4. Verify package.json for Material dependencies
5. Cross-reference with Material 15 official migration guide

SUCCESS CRITERIA:

- Every deprecated API usage documented
- Zero surprises during actual migration
- Clear, actionable migration plan
- Confidence in deployment safety
